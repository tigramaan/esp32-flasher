# Hardware-in-the-loop Runbook

## Безопасность

Использовать тестовые платы и резервные копии данных. HIL-02/HIL-03 изменяют
application partition; HIL-04 с `full erase` удаляет NVS. Перед каждым тестом
сверить вычисленную flash-карту, chip и flash size. Не отключать питание, кроме шага,
где interruption явно требуется.

Каждый прогон фиксирует: дата, commit, Programmer version, package/version,
board/chip, MAC, Windows version, результат и ссылку на log/CSV.

## HIL-01 — Detection and disconnect

1. Запустить EXE с уже работающей платой: порт выбирается, но плата не
   перезапускается, EN не удерживается, текущий UART/индикаторы продолжают работу.
2. Нажать refresh и несколько раз выбрать порт: DTR/RTS не переключаются, reset
   платы не происходит.
3. Подключить вторую плату: доступен явный выбор, автоматическая запись и active
   probe не начинаются.
4. Явно запустить операцию: chip/MAC/flash size определяются после нажатия кнопки.
5. Занять COM другим приложением или вызвать connect error: получить
   `PORT_BUSY`/connect error без hang; после освобождения порта плата загружается
   нормально и не остаётся в reset/ROM bootloader.
6. Отключить во время monitor: UI переходит в disconnected не позднее 2 секунд.

## HIL-02 — Factory-only update

1. Использовать плату с одним factory app partition и сохранённым NVS marker.
2. Выбрать конкретный application BIN с произвольным именем.
3. Первый старт должен вернуть подтверждение in-place риска.
4. Отменить: flash не изменяется.
5. Повторить и подтвердить: app записывается/verify, UART открывается.
6. Проверить UART boot и неизменный NVS marker.

## HIL-03 — OTA update

1. Зафиксировать активный slot и версию.
2. Обновить: Programmer должен выбрать неактивный slot.
3. После flash verify проверить новую версию и boot selection.
4. В отдельном прогоне отключить питание во время app write до otadata switch.
5. Восстановить питание: ранее активный образ должен загружаться.
6. Повторить с legacy rollback package и проверить firmware validation до marker.

## HIL-04 — Factory series

1. Выбрать обычную PlatformIO factory-папку, сверить карту и начать session.
2. Прошить 10 плат, каждый cycle запускать только кнопкой.
3. Настроить marker в производственном UI; на одной плате подавить marker до
   timeout, на одной отключить UART. Повторить без marker и проверить `OK` после
   flash verify с открытым монитором.
4. После каждого результата отключать плату и засекать готовность следующего
   cycle (не более 2 секунд).
5. Сопоставить total/passed/failed и CSV: ровно одна строка на cycle, MAC уникален.
6. Повторить один cycle с отдельно подтверждённым full erase.

## HIL-05 — UART responsiveness

1. Firmware выводит не менее 1 Мбит/с в течение 60 секунд после flash.
2. Переключать tabs, clear terminal и менять размер окна.
3. Windows не показывает «Не отвечает»; status update остаётся доступным.
4. Память стабилизируется благодаря лимиту 10 000 строк.

## HIL-06 — Standalone UART lifecycle

1. Запустить работающую плату, выбрать порт и открыть вкладку UART без прошивки:
   monitor подключается, плата не перезапускается.
2. Перейти на «Процесс» и обратно: поток не разрывается, чанки не теряются.
3. Нажать «Отключить», переключить вкладки: скрытого reconnect нет. Нажать
   «Подключить» и убедиться, что поток восстановлен.
4. Сменить baud, перезапустить EXE и проверить сохранённое значение.
5. Нажать «Перезапустить»: получить normal boot log без входа в ROM bootloader.
6. При подключённом direct monitor начать flash: UI переходит на «Процесс», UART
   заблокирован, `PORT_BUSY` отсутствует; после результата UART открывается.
7. Повторить на CP210x, CH340 и native USB Serial/JTAG, если они входят в парк
   поддерживаемых плат.
