Everything in one executable

From a customer update to a production bench

The desktop workflow stays small while the guards remain explicit: validate, connect, write, verify, restart, and monitor.

01

Single-BIN updates

Select any valid application BIN. The device partition table is read before writing, so the application is placed in a real application partition.

02

Safe OTA switching

When an inactive OTA slot exists, the new image is written and verified before boot metadata is switched.

03

PlatformIO factory flash

Choose the normal build folder. ESP32 Flasher parses the partition table and shows the computed multi-segment write map.

04

Integrated UART monitor

Monitor without flashing, change baud rate, reconnect explicitly, or restart the board in normal boot mode.

05

Production sessions

Track passed and failed boards, use an optional ready marker, and save one UTF-8 CSV row for every completed cycle.

06

Local by design

Firmware and UART output stay on the computer. There is no account, cloud firmware catalog, analytics, or telemetry.

Two clear workflows

Simple for customers. Repeatable for operators.

UPDATE MODE

One file, one connected board

  • Choose one application BIN with any file name
  • Read the live device partition layout
  • Prefer an inactive OTA slot
  • Require confirmation for a one-slot overwrite
  • Open the UART monitor after verification

PRODUCTION MODE

One build folder, many manual cycles

  • Use bootloader, partitions, and firmware BIN files
  • Compute and display the flash map
  • Flash at a fixed 921600 baud
  • Track passed and failed boards
  • Write local CSV reports after every cycle

Frequently asked questions

ESP32 Flasher, in plain terms

Does ESP32 Flasher require Python or esptool?

No. The Windows release is a standalone portable application with the flashing backend built in.

Can I update an ESP32 with one BIN file?

Yes. Select a valid application BIN. ESP32 Flasher reads the connected device partition table and chooses a safe application target when one is available.

What files are used for factory flashing?

Choose a PlatformIO folder containing bootloader.bin, partitions.bin, and firmware.bin. boot_app0.bin is optional.

Can the UART monitor be used without flashing?

Yes. Open the UART Monitor tab to connect passively, select a baud rate, disconnect, reconnect, or restart the board in normal boot mode.

Does the application upload firmware or serial data?

No. The desktop application has no telemetry or cloud backend. Firmware, logs, reports, and UART output stay on the local computer.

Why can Windows SmartScreen show a warning?

Public builds may be unsigned until Authenticode signing is configured. You can verify the downloaded file with the SHA-256 checksum published next to each release.
