# ADR-0006 — Изоляция flash I/O для отмены и таймаутов

**Статус**: Accepted, 2026-08-13
**Связанные требования**: REQ-015, REQ-022, REQ-028, REQ-029

## Контекст

Windows USB-UART драйвер или синхронный serial-вызов может не вернуть управление
в ожидаемый срок. Таймаут UI или флаг отмены не способны безопасно уничтожить
зависший Rust thread, поэтому COM handle остаётся занят, а приложение фактически
требует закрытия.

## Решение

ROM connect, erase, write и verify выполняются в отдельном процессе, запущенном
из того же portable EXE скрытым внутренним режимом. Родительский supervisor
получает типизированные события по stdout, хранит логи и результат, применяет
таймауты и ограниченный retry. Команда STOP или timeout завершает дочерний
процесс; Windows закрывает принадлежащие процессу COM handles.

Connect повторяется максимум три раза по 20 секунд. Retry разрешён только до
erase/write. После начала изменения flash timeout или STOP завершают операцию с
явным предупреждением о возможном частичном состоянии.

## Альтернативы

- Флаг `AtomicBool` между стадиями: не прерывает зависший системный вызов.
- `tokio::time::timeout` вокруг blocking task: возвращает UI, но не завершает
  thread и не освобождает COM.
- `TerminateThread`: оставляет процесс в неопределённом состоянии.
- Отдельный worker EXE: нарушает требование одного portable файла.

## Последствия

- Portable-поставка остаётся одним EXE.
- STOP гарантированно освобождает ресурсы worker-процесса.
- Worker protocol становится внутренним версионируемым контрактом.
- Запуск процесса добавляет небольшую задержку перед подключением.
